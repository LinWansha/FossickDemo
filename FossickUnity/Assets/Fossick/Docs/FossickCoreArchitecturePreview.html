Fossick Core Architecture

当前实现架构图。无阶段版本名；所有节点均对应现有 Core、Runtime、MapStudio、Preview 代码中的实际职责或类族。

Core玩法规则、矿井对象、局内数据、资源索引
Runtime正式矿井表现层，负责棋盘与格子渲染
MapStudio策划模板编辑、生成规则和地图预览
Preview独立试玩壳，用于验证核心玩法

1. 模块总览

Core 是玩法中心；MapStudio、Runtime、Preview 都依赖 Core，Core 不反向依赖它们。

2. Application 调用主线

所有外部操作先变成 Command，由 Session 编排系统执行，再用 Result 和 Snapshot 驱动表现与外部适配。

sequenceDiagram
  participant Input as HOP 或 Preview 输入
  participant Facade as FossickGameplayFacade
  participant Session as FossickGameplaySession
  participant Systems as FossickSystem 子系统
  participant Data as FossickGameplayData
  participant Adapters as FossickGameplayAdapters

  Input->>Facade: UseTool / Pickup / Preview
  Facade->>Session: Execute(FossickCommand)
  Session->>Systems: 按规则执行
  Systems->>Data: 修改局内数据
  Systems-->>Session: 写入 FossickActionResult
  Session-->>Facade: FossickActionResult + FossickSnapshot
  Facade->>Adapters: View / Animation / Reward / Storage / Telemetry
当前实现存在 `FossickGameplaySession`、`FossickGameplayFacade`、`FossickGameplayAdapters`、`FossickActionResult`、`FossickSnapshot`，与该图一致。

8. 实现一致性检查

Application 下存在 Session、Facade、Adapters、Commands、Events、Results。
Systems 下存在 Digging、Tools、Pickup、Visibility、Scrolling、Rewards、Generation。
Mine 下存在 Grid、Layers、Terrain、Regions、Fog、Rewards 对象族。
Reward 对象拆成 Embedded、Entities、Payloads，符合当前地形破坏后生成实体的规则。
Data 下存在 Gameplay、Mine、Inventory、Reward、Progress、Generation 数据根。
Visual 下存在 ArtCatalog、ArtLibrary、AutoTileResolver。
Runtime/Views 存在 FossickBoardView 和 FossickCellView，是正式表现层基础。
MapStudio 和 Preview 位于 Core 外，依赖 Core，不被 Core 反向引用。
